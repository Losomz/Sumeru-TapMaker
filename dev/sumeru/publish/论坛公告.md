# 论坛公告：发帖与「活动与公告」

更新公告、新手教程这类帖子，用 `taptap-cli` 发到自家论坛，再挂到游戏详情页的「活动与公告」。下面的流程和坑是 2026-11-06 在 doomsday-miner 实际发布时核实过的。

命令里的 `<A>` 是游戏的 appId，`<D>` 是厂商的 developerId。不知道就用 `taptap-identity` 查，不要猜。

## 谁拍板

| 步骤 | 影响 | 要不要用户同意 |
|---|---|---|
| 写稿、建草稿 | 只有自己能看到 | 不用，建完把预览链接给用户 |
| 发布帖子 | 公开，**撤不回** | 用户看过预览、明确说「可以发」 |
| 挂到「活动与公告」 | **一建就上线**，玩家马上能看到 | 用户同意，并选好置顶位置和展示时间 |

用户只说「发个帖」，不算同意发布。

## 流程

### 1. 写稿

- 更新公告：从 `docs/更新日志/模板.md` 复制到 `docs/更新日志/1.0.N/日志.md`（目录名用本次出包的 Maker 版本），写作规则在模板末尾。
  - 标题带版本号：「【更新公告】v0.N 一句话亮点」，只写 Maker 版本后两段（1.0.37 写 v0.37）。玩家在「活动与公告」里一眼就能看出是哪一版。
- 教程、常见问题这类长期挂着的帖子：放 `docs/社区公告/<标题>.md`。
- 数值、规则、按钮名都对照代码和游戏里的文字核实，不凭记忆写。
- 公告里的版本号只写后两段 `0.N`（[README.md](README.md) 规则 8），标题和正文一致，发出去就改不了。

### 2. 建草稿

1. 先查发帖选项：`taptap-cli community-management get-community-forum-publish-options --app-id <A>`。这个命令只接 `--app-id`，带 `--dev-id` 会报错。
   - 作者选项里有 `is_official: true` 的，就用官方身份 `"identity": "official"`。
   - 子版块默认「综合」，填 `"group_label_id": "0"`。
2. 把稿件转成正文节点，再建草稿：

   ```
   taptap-cli community-management create-community-topic-draft --app-id <A> --dev-id <D> --data @draft.json --dry-run
   ```

   先 `--dry-run` 看请求，没问题再换成 `--yes`。`draft.json` 的结构：

   ```json
   {"title":"…","contents":"<正文节点数组的 JSON 字符串>",
    "forum_bindings":[{"app_id":"<A>","group_label_id":"0","identity":"official","honor":{"mode":"inherit"}}]}
   ```

   - `contents` 是**字符串**，要把节点数组 `JSON.stringify` 一次再放进去，直接放数组会报 400。
   - Markdown 对应的节点：
     - `## 标题` → `{"type":"heading","info":{"level":2}}`
     - `- 列表项` → 连续几行合成一个 `list`，每行是一个 `list-item`，`"li-level": 1`（不能是 0）
     - `**粗体**` → `{"text":"…","bold":true}`
     - 其他非空行 → `paragraph`
     - 一级标题 `# …` 不进正文，作为 `title`。
   - 正文要配图时，图片先用 `+upload-image` 上传，节点里的宽高要用上传返回的值，填 0 会被丢掉。
   - `--data @文件` 的路径必须在当前目录里，所以要在放 `draft.json` 的目录下运行。临时文件用完删掉。
3. 返回里的 `preview_url` 是帖子编辑页，交给用户看。要改就用 `update-community-topic-draft` 改，整份替换，改完再给一次预览。

### 3. 发布

```
taptap-cli community-management publish-community-topic-draft --app-id <A> --dev-id <D> --data @publish.json --yes
```

- `publish.json` 是 `{"draft_id":"…","document":{…和建草稿时一样的完整文档…}}`。
  - `draft_id` 放在最外层，放进 `document` 会报 400。
  - `forum_bindings` 要原样带上，传空数组等于把帖子从论坛撤下。
- 返回的 `moment_id` 是下一步要用的帖子编号，链接是 `https://www.taptap.cn/moment/<moment_id>`。
- 刚发的帖子在审核中，可能只有自己能看到，这不是失败，不要重发。
- 发出去以后 CLI 没法改也没法删，只能到 TapTap 网页上处理。

### 4. 记下帖子链接

- 更新公告：填进 `docs/更新日志/README.md` 版本表的「帖子」列。
- 其他帖子：填进 `docs/社区公告/README.md`。

链接统一用 `https://www.taptap.cn/moment/<moment_id>`，下一步只认这种。忘了编号的话，用这个命令查（这个命令要带 `--dev-id`）：

```
taptap-cli community-management list-community-moments --app-id <A> --dev-id <D> --data '{"order":"published","page_size":30}'
```

### 5. 挂到「活动与公告」

1. **先查重、看容量**：
   - `taptap-cli whats-new find-whats-new-by-url --app-id <A> --dev-id <D> --data '{"url":"<帖子链接>"}'`：这个帖子挂过的话，就去改那一条，不要重复建。
   - `taptap-cli whats-new get-whats-new-overview --app-id <A> --dev-id <D>`：
     - 公告类最多 2 条在线；
     - 详情页置顶最多 2 条，PC 库置顶最多 3 条。
   - 满了就列出占着的条目，让用户选下线哪条。不要自己下线。
2. **问用户两件事**：
   - **置顶位置**：不置顶、游戏详情页、PC 库、两处都置顶。没说就问，不要默认。
   - **展示到什么时候**：平台不支持永久展示，必须给一个结束时间。参考：教程类一年；更新公告 30 天，下次更新时换新的。
3. **创建**（一建就上线）：

   ```
   taptap-cli whats-new create-whats-new --app-id <A> --dev-id <D> --idempotency-key <唯一键> --yes \
     --data '{"url":"https://www.taptap.cn/moment/<moment_id>","type":"announcement","label_type":"announcement","start_time":0,"end_time":<结束时间戳>,"top_types":["app_detail","pc_inventory"]}'
   ```

   - `url` 只认 `/moment/<moment_id>` 链接。帖子列表返回的 `/topic/<编号>` 链接会被拒，报「错误的链接」。
   - `type`、`label_type` 都填 `announcement`，建好以后改不了。
   - `start_time` 填 0 表示从现在开始。`end_time` 是秒级时间戳，比如 `Date.parse("2027-11-06T23:59:59+08:00")/1000`。
   - `top_types`：`app_detail` 是游戏详情页，`pc_inventory` 是 PC 库，空数组是不置顶。
   - 置顶的先后按创建顺序排。想让更新公告排在第一条，就先建它。
4. **回读核对**：用 `taptap-cli whats-new get-whats-new --app-id <A> --dev-id <D> --data '{"content_id":<编号>}'` 看状态是否在线、是否失效、起止时间和置顶位置对不对，再读一次总览。
   - **看一眼卡片标题**。2026-11-06 doomsday-miner 的「【更新公告】添加5-10关敌人」，卡片标题变成了正文开头那句话；同一天发的教程帖标题正常，原因没查明。卡片标题不能单独改，不对的话只能换帖子。
   - 配置上线了，不代表玩家已经能看到，要到详情页上实际看一眼。

### 6. 发新的更新公告时

公告位只有 2 个。先下线旧的更新公告，再建新的。下线也是写操作，先 `--dry-run`，确认是哪一条再换成 `--yes`：

```
taptap-cli whats-new update-whats-new-status --app-id <A> --dev-id <D> --idempotency-key <唯一键> --data '{"content_id":<旧条目编号>,"status":"offline"}' --dry-run
```

只想改展示时间或置顶，用 `update-whats-new`，不要下线重建。
