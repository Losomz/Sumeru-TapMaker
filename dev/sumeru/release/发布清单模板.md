# 发布清单 · {游戏名} {版本}（公告 {公告}）

> `release.js new` 自动从模板复制到 `docs/更新日志/{版本}/发布清单.md`。从上往下做，做完一步打勾、填“记录”。
> 顺序和选项是定死的，不另外翻文档做决定。跳过哪一步要写原因。每步做到哪也记在同目录的 `发布记录.json`，中途断了重跑同一条命令接着做。
> 命令都在项目根目录跑：`node dev/sumeru/release/release.js <命令>`（下面简写成 `release <命令>`）。
> 谁做：**Claude** = 我来跑；**你** = 只有你能做的（看预览点头、在 Maker 发布页点按钮）。

## 定死的选项（不用每次再选）

| 项 | 固定为 |
|---|---|
| 上架状态 | 保持“提供游玩”。发布页只点「保持状态并更新版本」，**不点「改为公开测试」** |
| 平台 | 只上手机（`app_platforms = "1"`），不加电脑端 |
| 版本号 | 本次 = 下一个包的 Maker 号（云端号出过包才 +1，没出过不涨）；公告写后两段（1.0.8 → v0.8）；数据后台 `appVersion` 同一个号 |
| 更新公告 | 每次都发：官方身份、“综合”版块，标题“【更新公告】{公告} 一句话亮点”，结尾带交流群。版本上线后才发 |
| 活动与公告 | 新公告顶替上一条更新公告，详情页置顶、排第一条、展示 30 天；新手教程、意见反馈不动 |
| 测试 | 全量测试，`dev/release.json` 里 `test.must` 的每一句都要出现，失败 0 条 |
| 存档 | 读档永不清档；测试逐份读上线过的真存档样本，没有上一版的样本不发 |
| 发布页 | 构建期间不开；构建完我提醒你再开 |

## 一、出稿

- [ ] **1. 定版本号**　Claude · `release new`
  同步云端，算出本次版本号，建本目录（本清单、公告稿 `日志.md`、`发布记录.json`）。
  记录：上一版 ____ → 本次 {版本}
- [ ] **2. 出稿子、建草稿**　Claude · 写 `日志.md` → `release draft`
  照模板写更新公告（配图可选，写成 `![宣传图](宣传图.jpg)`）。`draft` 上传配图、在 TapTap 建草稿（玩家看不到），给出预览链接。
  改了玩法、商店截图或简介也要改的，一起出改稿（不改写“无”）。记录：公告标题 ________；其他稿 ________
- [ ] **3. 你看预览、点头**　你 → Claude · `release approve`
  你说“可以发”，我跑 `approve` 记下。之后再改稿子，确认自动作废，要重来一遍。记录：____ 点头
  这版不另写公告、沿用已发的（你说沿用哪一版）：第 2、3 步换成 `release reuse --from 1.0.N --note "这版改了什么"`。

## 二、备包（Claude 一键：`release prepare`）

- [ ] **4. 写版本号**　`appVersion` 改成 {版本}，单独提交。
- [ ] **5. 全量测试**　跑完看结果，不过就停。记录：断言 ____ 条，提交 ____
- [ ] **6. 发布前检查（只读）**　云端干净、本地不落后、版本号对、测试是当前提交、有上一版的存档样本（存档版本号变了会提示）、公告已确认、TapTap 没有审核中的版本、只上手机、不是公开测试、详情页能玩、物料检查过、公告位够。
  有一项不过就停，报给你。

## 三、发包

- [ ] **7. 改商店物料**（第 2 步有改稿才做）　Claude
  截图、简介照 `dev/sumeru/publish/README.md` 写进 TapTap 草稿并读回核对。没有就写“无”。
- [ ] **8. 构建**　Claude · Maker 构建（`maker_build_current_directory`）
  先跟你说“开始构建，先别开发布页”，构建成功再往下。记录：提交 ____
- [ ] **9. 你点发布**　你
  打开 Maker「发布到 TapTap」页 → **刷新**（开着的旧页面会把旧简介写回去）→ 确认顶上没有红字 → 选「保持状态并更新版本」→ 点**一次**。点完告诉我。

## 四、收尾（Claude 一键：`release finish`）

- [ ] **10. 核对上线**　同步发布页写的 `project.json`；有新包（Maker 号对不上只提示、照样收尾）；TapTap 新版本已上线；详情页按钮是“打开 APP 试玩”。
  审核还没过，`finish` 停在这一步，过几分钟重跑，你不用重复点。记录：TapTap 版本 ____，spark ____
  **被拒了**：`finish` 记下原因。只改简介等资料 → 改 `project.json` 后 `release resubmit`，你点头再加 `--yes` 提审，**别回发布页点**；要改代码 → `release renumber`（重建版本号必 +1），再从第 4 步走。记录：____
- [ ] **11. 发更新公告**　发第 3 步确认过的那份草稿。记录：帖子 ____
- [ ] **12. 换活动与公告**　下线旧的更新公告，挂新的、排详情页第一条，读回核对。记录：编号 ____
- [ ] **13. 记录、提交**　出这一版的存档样本，版本表加一行，提交本清单、`发布记录.json` 和样本，出发布报告。
- [ ] **14. 第二天看数据**　Claude
  数据后台 {版本} 有没有来数、有没有报错事件。记录：____

随时看全局：`release status`（版本一览，只读）。
